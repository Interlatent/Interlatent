# 0038 — One coordinator protocol, N deployments; the dashboard stops being special

- Status: Accepted
- Date: 2026-08-06
- Supersedes: [0023](0023-self-hosted-policy-server-returns.md) (its
  "the dashboard remains the only control plane" bullet, and with it the
  finality of deleted ADR 0001)

> Numbering note: this repo's ADR *files* run 0011–0023, but code comments cite
> platform-repo ADR numbers up to 0037 (`recorder.py` cites 0024,
> `daemon.py` cites 0037). 0038 is the next number free in **both** series.
> The gap is deliberate; don't try to reconcile the two series.

## Context

ADR 0023 (2026-07-30) brought back `packages/server/` after PR #2 ("no-server",
2026-06-23) had deleted this repo's entire self-hosting stack. It brought back
half deliberately — the box, not the control plane — and said so:

> What nobody wants back is the *offline coordinator*: a second control plane
> forked every flow into two modes and is why the 2026-06 stack collapsed.
>
> **The dashboard remains the only control plane** (deleted ADR 0001 stays
> dead). No offline mode, no local session brokering.

That verdict is being reversed, and the reason it can be reversed safely is
that **it blamed the wrong noun**. Re-read the sentence: the fault it names is
*"forked every flow into two modes"*, not *"a coordinator existed"*. The
2026-06 stack had a node-facing `/api/v1/nodes/*` surface **and** a bespoke
`/admin/*` surface with its own `CoordinatorClient`, so every operator flow had
a dashboard spelling and a coordinator spelling. Two clients, two payload
shapes, two sets of bugs. That is what collapsed.

Meanwhile the pressure that produced ADR 0023 has not let up. In the week since
it was accepted, every unreleased change to `interlatent-serve` has been about
teaching a self-hosted box to survive without the dashboard's help: `6813edc`
made a box honour its own `--warmup-policy` (silently dropped the moment
registration succeeded, which is always), `7e56419` added `--warmup-image-keys`
because a MolmoAct2 pre-warm was otherwise unreachable without an environment to
go configure, and the same work made registration log the endpoint it resolved.
Each is a patch around one fact: a box that owns its own hardware still cannot
own its own configuration. The coupling is load-bearing in four places:

- `interlatent-serve` exits if `POST /compute/boxes/register` fails.
- Every gRPC RPC re-checks `GET /compute/boxes/{id}/authz`.
- The dashboard issues the presigned URLs that are the only dataset sink.
- The teleop token *and the relay address* are minted per reconnect.

## Decision

**One protocol, one code path, N deployments.**

The HTTP surface the SDK already speaks to the dashboard is named, frozen and
documented as the **Interlatent Coordinator Protocol**
(`docs/coordinator-protocol.md`, `interlatent.coordinator.protocol`). The hosted
dashboard becomes one implementation of it. `interlatent up` ships another.

Three commitments make that more than a rename:

1. **No mode branch.** The SDK contains no `if hosted: … else: …`. A step that
   introduces a branch on "is this the dashboard?" is a step done wrong. The
   dashboard keeps working not through a compatibility path but because it
   already implements the contract.

2. **`/api/v1/*` only. No `/admin/*`, no `CoordinatorClient`.** This is the
   concrete answer to 0023's objection, and it is the whole difference between
   this ADR and deleted ADR 0001. One HTTP client serves the CLI, the node, the
   box and the teleop web app. `interlatent gpu add` is
   `POST /api/v1/compute/boxes/register` — the same route `interlatent-serve`
   calls. The genuinely coordinator-shaped verb that remains (setting the
   recording destination) is declared `coordinator-only` in the protocol so a
   404 from the dashboard is reported by name.

3. **No hosted default.** The coordinator address is required at every entry
   point. `https://interlatent.com` stops being a fallback baked into eight
   places and becomes a value you pass. This is what makes claim (1) checkable:
   with a default, "one code path" is an aspiration nobody can test; without
   one, pointing at a coordinator is the only way anything runs.

Consequent to those, and decided here so they are not re-litigated per-step:

- **The coordinator is the token authority**, not a trust-the-network box. It
  mints `ilnode_` tokens on pair, guards operator routes with an `ilop_` key
  generated by `interlatent up`, and answers `/compute/boxes/{id}/authz`. ADR
  0023's "guarded by default" stance is preserved verbatim; deleted ADR 0001's
  "the network is the trust boundary" is **rejected**, not restored.
- **Teleop is control-plane work too.** The 2026-06 coordinator hard-404'd
  teleop-token mints. This one brokers teleop sessions and ships an embedded
  WebTransport relay, because "managed by the CLI alone" is not true if VR
  requires a hosted service.

## Consequences

- `CONTEXT.md`'s **Node** entry loses its *"Avoid: calling this a
  'coordinator'"* rule, which ADR 0023 had explicitly re-affirmed. The word is
  now the correct one and has a glossary entry of its own.
- Dropping the hosted default is a **breaking change**: anything invoking
  `interlatent`, `interlatent-preflight`, `interlatent-serve` or `Interlatent()`
  without an explicit base was relying on it. Paired nodes are unaffected —
  `node.toml` has always stored the address — so the break is confined to
  interactive and scripted use, with a one-line fix.
- The dashboard must keep serving the mandatory tier. It does today; the
  protocol document turns that from an accident into a contract, and
  `tests/test_coordinator_protocol.py` turns the document into an assertion.
- **The open-core line moves.** After this, the OSS does inference, collection
  and teleop with no account, and what remains hosted is the dataset store, the
  merge pipeline, offline policy improvement and the annotation stack.
  `docs/going-to-cloud.md` already frames those as the paid layer; they are now
  the *whole* paid layer. That is a product decision taken deliberately here
  rather than discovered later.
- ADR 0012's open-core boundary ("the SDK ships no IK solver") is already
  contradicted by `teleop/teleop-web/src/lib/teleop/dlsSolver.ts`, an in-browser
  solver living in this repo since the QUIC path landed. That drift is
  pre-existing and gets amended alongside this work, not by it.

## Considered alternatives

- **Two modes: keep the dashboard path, add a local one beside it.** Fastest to
  land and exactly what ADR 0023 identifies as the cause of the last collapse.
  Rejected on the record.
- **Keep the dashboard the only control plane, keep patching the box.** The
  status quo ADR 0023 chose. Rejected because the five post-0023 commits show
  the patch surface growing, not converging, and because it cannot deliver a
  robot stack that runs on a disconnected network at all.
- **Restore deleted ADR 0001 as-written**, `/admin/*` and unauthenticated.
  Rejected twice over: the dual surface is the failure mode, and binding an
  unauthenticated control plane on `0.0.0.0` walks back a security decision
  0023 made deliberately — anyone on the LAN could move your arm.
